# Release v1.1.0 — 2026-11-18

## Summary

Every place the dashboard displays an AI **thesis** now renders as an orderly, labelled record instead of one dense paragraph: a scannable structure header, a fact row for SL / TP / R:R, a labelled clause list, and the untouched original text under **RAW**. The same information is exposed to machines through a stable JSON mirror on every entry, so a human and an AI agent read the same thing.

The change is display-only. `data.json`, the trading bot, the sync pipeline and the writer's prompt are untouched. No new dependencies, no build step, no external requests — still one `index.html`.

**Version type:** minor (new feature, backward compatible)

## What changed

### Added

- **One parser for the whole page** (`parseThesis`, contract [`THESIS-1`](../thesis-contract.md)) used by all four thesis surfaces:
  - open position card — *AI Entry Thesis*;
  - pending order card — *Trap Thesis*;
  - closed-trade drawer — *Entry Thesis* + *Post-Trade Lesson*;
  - AI stream — decision-journal rows and lessons.
- **A shared thesis component** built on the existing prop-desk system (`--brass` / `--jade` / `--red`, mono uppercase labels, tabular numerals):
  - structure chips for the timeframe set and bias (`H4 H1 M15 · BEAR`);
  - a labelled fact row for **Stop loss / Take profit / Reward-risk / RSI** where the text states them;
  - an ordered clause list with semantic labels — **Alignment, Setup, Context, Stop loss, Take profit, Management, Risk, No trade, Result, Why, Rule** — instead of a wall of text;
  - Thai lessons as readable prose with the numbers and levels emphasised in mono, not a paragraph blob;
  - the original string preserved verbatim in a keyboard-operable **RAW** disclosure.
- **Machine mirror** on every component root: `data-thesis-json` (the full `THESIS-1` object), `data-thesis-version`, `data-thesis-kind`, `data-thesis-mode`, `data-thesis-ok`, and `data-thesis-context` (surface, title, symbol, side), plus a screen-reader heading. No content lives only in CSS or an image.
- **Four parse modes** with contract-defined rendering: `clauses` (labelled list), `prose` (one paragraph plus fact chips), `raw` (escaped text only, no chips), `boilerplate` (muted system line).
- **Graceful degradation**: a missing or `null` reason keeps the existing neutral message (`ไม่มีบันทึกเหตุผลสำหรับไม้นี้ (legacy trade)`), unparseable text falls back to plain text in the same container, and no `undefined` / `null` / `NaN` is ever rendered.
- **Documentation**: [`docs/thesis-contract.md`](../thesis-contract.md) (`THESIS-1`, the agreed grammar, fields, labels and parsing rules) and the proposal-only [`docs/thesis-prompt-addendum.md`](../thesis-prompt-addendum.md) (not applied to the live prompt).

### Changed

- Position, order, trade and stream thesis text is now segmented losslessly at `;` and `,` (and `. ` where the writer uses prose), with parentheses protected, so `within ADR`, `(90.72)` and `(64743/64803)` stay intact.
- Pending orders keep the **computed** R:R from trigger / SL / TP as the authoritative figure; the thesis fact row shows the R:R *as written* and labels it `as written` when both exist.
- Numbers in clause text render exactly as written (no re-rounding). Formatted values only appear in the separate fact row.
- Two new rows were added to the fact block for context already present in the text: RSI (`H1 · oversold`) and, where stated, reward-risk.
- README features, controls and project structure now document the thesis display and the contract.

### Fixed

- Thesis text no longer renders as an unstructured `<p>`; long Thai lessons no longer read as a wall of text, and mixed Thai/English no longer breaks the card layout.
- `details` summaries now expose the structure (timeframes + bias) before the card is opened.

### Accessibility

- Disclosure `<summary>` elements are keyboard-focusable with a visible brass focus ring (verified: focus outline `solid 1px rgb(216,185,122)`).
- Semantic markup: `<h3>` heading per entry (visually hidden where the surface already has one), `<dl>` facts with real `<dt>` labels, `<ol>` clause list, `<details>` for raw text.
- `prefers-reduced-motion` is respected by the existing global rule; no new motion was introduced.
- Chips carry text labels, never colour alone.

## Who it affects

- **Dashboard visitors** — the same data, in a more scannable form; no login, no new controls. Expand *AI Entry Thesis* / *Trap Thesis* / a trade row to see the structured record and its RAW text.
- **The operator** — nothing to change in the bot or the sync pipeline. `data.json` keeps exactly the same shape; the thesis fields are parsed in the browser.
- **AI agents / tools reading the page** — every thesis entry now exposes a stable, complete JSON object via `data-thesis-json`, so an agent can read bias, timeframes, SL/TP, R:R, clause labels and the raw string without screen-scraping prose.
- **Anyone reading the source** — the grammar and field names are documented in `docs/thesis-contract.md`; the renderer implements it exactly.

## How to use / upgrade

1. Open the live dashboard: <https://plub-supanut.github.io/mt5-ai-performance/>
2. To read a thesis: expand **AI Entry Thesis** or **Trap Thesis** on a position/order, open a trade row, or switch the AI stream between **Decision journal** and **Lessons learned**. Use **RAW** at the bottom of any thesis to see exactly what the bot wrote.
3. For machine access, read `data-thesis-json` on the thesis root (JSON, `THESIS-1` shape: `version`, `kind`, `raw`, `ok`, `lang`, `clauses`, `facts`, `parse`). `data-thesis-json="null"` means the entry has no thesis text (legacy trade or an empty journal row).
4. No migration, install or configuration is required. The parser runs inline in the page; there is no new endpoint.

## Known issues

- **Heuristic parser.** Clause boundaries and labels are deterministic heuristics. A future writer change that uses a new punctuation style may degrade a thesis to `prose` or `raw`; the original text is always shown, and no error is displayed. This is by design, not a failure.
- **Legacy trades.** Trades captured before reason logging (`entry_reason: null`) show the neutral *"ไม่มีบันทึกเหตุผลสำหรับไม้นี้ (legacy trade)"* message, not a fabricated thesis.
- **Empty journal rows.** `LEARN` rows carry neither `summary` nor `reason`; the dashboard shows a neutral placeholder. The lesson itself lives in the Lessons tab, linked by position id.
- **One unlabelled Thai clause.** One lesson sentence ("หากโครงสร้าง … สามารถวาง TP …") is classified as `NOTE` under `THESIS-1` and renders as plain prose without a label. The contract now documents `NOTE` as legal in lessons.
- **R:R two sources.** For pending orders, the card's computed R:R can differ from the sentence's "as written" value; the thesis row is labelled `as written` so they are not confused.
- **Explicit strategy fields are still parsed, not authored.** Invalidation/confidence fields do not exist in `data.json` yet; `docs/thesis-prompt-addendum.md` is a proposal and the live bot prompt is unchanged.
- **No HTML sanitisation beyond escaping.** All thesis text is escaped with the page's existing `esc()`; no HTML is constructed from parsed text.
